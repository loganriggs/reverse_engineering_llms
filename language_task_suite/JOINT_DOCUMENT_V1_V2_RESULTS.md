# Joint document language: sampled rules and learning limits

The current joint-document pilot samples every token from an exact distribution determined by the visible prefix. It combines name-conditioned verb preferences, same-name verb induction, section-topic and recent-place verb proposals, speaker claims that bias later object mentions, item–attribute–speaker questions, section numbers, and bracket closure in **one stream**. Full next-token cross-entropy trains the models; task labels are used only for evaluation. This is a controlled diagnostic language, not a realistic web-text distribution.

[`joint_document_v1.py`](joint_document_v1.py) defines the base grammar. A document starts `Report : place .` or `Guide : place .`, then mixes profiles (`Nora is a pilot .`), sections (`Part 1 : park .`), narratives, claims (`According to Nora , the photo is fragile .`), and questions (`Who described the photo as fragile ? Answer : Nora .`). Brackets can interrupt a narrative, with the closer determined by the opener. A narrative verb is drawn from a named mixture: 50% name-specific bigram, 25% last verb for that name when available, 15% current section/title topic, and 10% most recent explicit place when available; missing components are renormalized. Claim matching boosts an object with 45% proposal mass. Articles `a`/`an` obey noun-initial vowel support. There is **no newline process or learned capitalization rule**; names and sentence starts have fixed token forms. The title words `Report` and `Guide` do not select different downstream grammars.

[`joint_document_v2.py`](joint_document_v2.py) adds reference and task-rich rates to the same grammar. It favors multiple claim speakers and distinct attributes on the same item. In the task-rich regime, a source question is allowed only when the item has been claimed by at least two speakers. Its exact answer depends on the queried attribute. A role-word change in an earlier profile is an oracle no-effect control. The reference and task-rich rates are research choices, **not** FineWeb-calibrated estimates.

The [V1 oracle audit](results/joint_document_v1_audit_n200_l256.json) replayed every prefix in 200 independent 256-token streams (51,200 positions), including supported edits. The [V2 reference](results/joint_document_v2_reference_audit_n200.json) and [task-rich](results/joint_document_v2_task_rich_audit_n200.json) audits likewise replayed 51,200 positions each. V2 task-rich yielded 1,254 source-answer sites; all 1,254 queried items had multiple speakers and all 1,254 supported attribute edits changed the oracle answer. The last-claim-speaker shortcut was correct on 40.4% of those sites. In V1, that shortcut was correct on 79.3% of 2,168 fresh source questions, while only 0.5% of queried items had multiple speakers. V1 aggregate source accuracy was therefore misleading.

The natural-form screen is negative. In the first 100 alphabetic words of 49 independent V2 task-rich samples, there were 352 distinct types, 50 singletons, and 36.9% of tokens belonged to the ten most common types. The comparable [FineWeb preview inventory](results/fineweb_predictive_inventory_skip23000_n64.json) has 1,993 types, 1,336 singletons, and a 21.4% top-ten share. The synthetic vocabulary contains only 500 total tokens. Some noun and other lexical lists use Zipf-shaped proposal weights, but the overall stream is **not calibrated to FineWeb's rank-frequency or genre distribution**. Its repeated templates are apparent in the literal samples generated by [`joint_document_v2.py`](joint_document_v2.py) with seeds 27001–27010, ten excerpts of which were shown in the research conversation.

## Bilinear model results

[`train_joint_document_v1.py`](train_joint_document_v1.py) and [`train_joint_document_v2.py`](train_joint_document_v2.py) use the existing bilinear attention/MLP model with RMSNorm, four heads, width 64, and one to four blocks. Each depth has one training seed and 1,000 full-next-token AdamW steps on 8,000 independently sampled 256-token documents, with 1,000 fresh evaluation documents. V2 trains on task-rich documents and evaluates on both task-rich and reference-rate documents. Exact document overlap with the training set is zero; this is **not** a whole-task or whole-combination training holdout.

The [full V2 JSON](results/joint_document_v2_bilinear_depth1_4_1000.json) includes reference-rate scores, section-number accuracy, and claim-linked-item KL. Overall NLL and easier tasks improve with depth. The contrastive source questions stay near the 40.4% last-claim baseline. The V1 [training results](results/joint_document_v1_bilinear_depth1_4_1000.json) had 75–78% source accuracy, but its [shortcut audit](results/joint_document_v1_shortcuts_n1000.json) showed why that was not binding evidence.

For V1, [fresh source-key edits](results/joint_document_v1_depth4_causal_n100.json) barely changed depth-four source answers (candidate-normalized total variation 0.0035 versus oracle 1.0); bracket-opener edits had total variation 0.997 versus oracle 1.0. The V2 causal test is in [`eval_joint_document_v2_causal.py`](eval_joint_document_v2_causal.py). The source edit changes only the queried attribute, preserving the object, sentence frame, claim history, and support; a prior-profile role edit is a nuisance control. Across two independent fresh panels of [653](results/joint_document_v2_depth4_task_rich_causal_n100.json) and [640](results/joint_document_v2_depth4_task_rich_causal_n100_replication.json) paired source questions, depth four has attribute-edit total variation **0.0043/0.0040** versus oracle **1.0**, similar to nuisance-role variation **0.0045/0.0049** versus oracle **0.0**. Bracket-opener total variation is **0.9984/0.9980** versus oracle **1.0**. Candidate-normalized probabilities are useful for this paired comparison but are not full-vocabulary accuracy.

These data support bracket closure and section numbering as competent probes. Mixed-verb and claim-linked-item distributions improve but remain imperfect. The current source-binding model is **not** eligible as a recovered semantic circuit: it has not passed the oracle prediction or causal edit gate. No task discovery or end-to-end canonical attention decomposition is claimed here.

## Course correction

Stop interpreting aggregate loss or source-answer accuracy on V1 as semantic binding. Keep V2 as a contrastive negative-control benchmark. The next language version should make document genre a real generative variable: court-style claims and citations, encyclopedia-style entity descriptions and sections, procedural guides/lists, and worked math problems should have different vocabulary, syntax, formatting, and rule prevalence. An exact prefix oracle can marginalize over a genre that is only partially signaled by early text, allowing genre evidence to accumulate. Calibrate reference mixture weights and lexical/sentence-form statistics on independent natural-text samples, while keeping an explicitly oversampled task-rich panel for causal tests. Carry over competent bracket/number/local-rule circuits and preserve whole-task or whole-combination holdouts for featurizer and canonicalization tests.
