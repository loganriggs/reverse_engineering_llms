# Joint natural-carrier rule coverage (2026-11-04)

The [single-rule surname model](FINEWEB_SURNAME_COPY_PILOT.md) nearly memorized its training pairs and did not learn reliable copying on held-out sources. A next model should see several rule families and more independent source prose. This audit asks whether the **same FineWeb documents and 256-token contexts** contain opportunities for surname reuse together with bracket closing, repeated three-letter codes, numbered lists, or spelling style. It is a feasibility gate, not a trained joint model.

The existing [corpus rule reference sampler](corpus_rule_reference_dgp.py) already provides length-preserving bracket/list edits and literal code/style sites. The new [paired wrapper](corpus_surname_joint_dgp.py) samples two **same-length** replacement surnames absent from an eligible passage and replays identical other rule choices in both arms. This preserves character offsets. It requires at least 20 words from the first to the second surname mention. The tokenized sampler accepts a surname site only when the source and target are single, identical GPT-2 BPE tokens in one ordinary nonoverlapping 256-token chunk. Both arms must preserve the other rule-site spans, and they may differ in text only at the replaced surname spans. The scored rule is exact string copying, not verified person coreference.

Among the 198 training contexts with another rule site, 136 have a bracket site, 51 a repeated-code site, 31 a spelling-style site, and one a numbered-list site; counts overlap. The independent panel has 21/7/3 bracket/code/style overlaps and zero aligned list overlaps. The [source-level train](results/fineweb_surname_joint_coverage_train_10k.json) and [independent](results/fineweb_surname_joint_coverage_test_2k.json) audits measure eligibility only. The [token-level train](results/fineweb_surname_joint_token_alignment_train_10k.json) and [independent](results/fineweb_surname_joint_token_alignment_test_2k.json) audits enforce both-arm, same-context alignment. No source prose is committed.

This supports a joint-stream pilot mainly for surname + bracket, with some code and style examples. It does **not** support treating lists as a well-covered co-occurring rule, nor does it establish human-quality entity identity, model competence, natural task rates, or an all-token oracle. Same-length surname filtering and PERSON tagging select a subset of FineWeb. We must retain unselected source documents in any future training stream to avoid turning the whole distribution into name-heavy prose.

The next deliverable is a source-disjoint, unselected mixed cache with ordinary full-token loss and explicit site tags, including paired surname edits only when eligible. A bilinear model should then be evaluated separately on each rule and on held-out combinations. Surname copying needs paired full-vocabulary prediction and edit-direction gates; brackets/code/style need their own visible-rule and causal checks. Only behaviorally learned rules qualify for weight-sparsity or canonical-basis comparisons. Stop expanding this carrier if the paired multi-rule model again fits training edits while failing held-out sources, and return to broader source diversity or a better sampled semantic renderer.
