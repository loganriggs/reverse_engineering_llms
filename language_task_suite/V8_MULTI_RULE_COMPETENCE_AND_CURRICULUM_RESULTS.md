# Can one v8 bilinear teacher perform both section and source binding?

The [color-edge featurizer follow-up](V8_SECTION_COLOR_EDGE_SUPERVISION_RESULTS.md) exposed a bottleneck: the two frozen three-layer v8 teachers use the requested section number, but barely follow the queried object in source/speaker questions. Interpreting a feature as a **shared correct language computation** requires the model to perform both tasks. This experiment audits existing checkpoints on common fresh exact-oracle and supported-edit panels, then tests task-frequency and curriculum interventions.

The [common auditor](audit_v8_multirule_teacher.py) evaluates a frozen model on the original v8 generator distribution. It reports exact-oracle next-token KL at verb, object, question, source and section sites, plus answer accuracy/CE and edit-to-oracle errors for three source and three section edit families. It checks that right padding leaves valid answer probabilities unchanged. The first audit uses fresh source/section/joint seeds `88001/88002/88003`, with 224 source edit pairs, 207 section edit pairs, and 1,024 joint streams; a second independent panel uses `88011/88012/88013`. The source-key and section-key edits are supported by the generator and have oracle probability-change L1 of 2. An edit-to-oracle L1 near 2 with a tiny native response means the model is effectively ignoring the key.

No existing width-64 checkpoint clears a joint task-competence screen. The scratch-balanced model has source-query answer accuracy `.469` but source-query edit error `2.001` and section-key accuracy `.446` on the first panel. The section-balanced seed-1/seed-4 models have section-key accuracy `.867/.821` but source-query accuracy `.169/.100` and source-query edit error `2.013/2.006`. Their source-answer oracle KL is `2.079/2.087`, versus section-answer KL `.319/.367`. Curriculum-only section checkpoints are still worse on source. The source error is a *causal* failure, not merely a calibration score.

## Matched source-heavy continuation

From the **same** section-balanced seed-1 checkpoint, two arms ran 600 updates with the same width-64, three-layer, four-head RMSNorm bilinear model; optimizer, seed `301`, batch 32×256 tokens, learning rate `.001`, exact-oracle and counterfactual loss weights, and all other generator parameters match. The control retains quote/source start rates `.08/.15`; the source-heavy arm uses `.30/.35`. A same-seed 64-stream count found source-answer sites `14`→`147` and section-answer sites `110`→`87`. This intentionally oversamples source supervision; it is **not** a claim of greater FineWeb realism. The training configurations differ only in those two rates and output directory. Evaluation fixes the original generator distribution for both arms.

On the first common panel, source-heavy sampling lowers source-answer KL from `2.093` (matched control) to `1.955` and raises source-query answer accuracy from `.206` to `.319`. Section-key accuracy also rises `.867`→`.900` and key-edit error falls `.634`→`.516`. A second fresh panel reproduces the direction: source KL `2.001`→`1.881`, source-query accuracy `.191`→`.283`, section accuracy `.933`→`.942`. But source-query edit error remains `2.01–2.04` in both arms, with native response L1 only `.016–.047`. More source examples improve predictions without teaching the queried-object dependency.

## Short source curriculum and long transfer

The [short curriculum](pretrain_v8_source_from_section.py) uses the **same v8 vocabulary and model architecture** initialized from the section-balanced seed-1 checkpoint. It asks which of two claim objects was spoken by which speaker in a 56-token supported prefix. An exact-oracle audit checked 256 training-stage cases and 256 stage-heldout speaker/object pairing cases, each under the original and four grammar-valid edits; all prefix transitions and answers passed. The initializing joint model already saw every pairing, so this stage split is **not** a whole-training pair holdout.

At learning rate `.003` and batch 256, the short run reached source-answer accuracy `.996/.977` (allowed/stage-heldout) by step 1,000 and `1.000/1.000` by step 1,500, with near-zero short query-edit error. Its step-1,500 snapshot still fails zero-shot on full v8 streams: source-query accuracy `.219`, query-edit error `2.615`, and section-key accuracy `.021` on the same first common panel. The short skill transfers only if later joint training adapts it and restores the other task.

Initializing a **source-heavy** 600-update joint continuation from that step-1,500 short checkpoint uses exactly the same long-stream seed and joint-stage settings as the direct source-heavy arm. On a new common panel (`88021/88022/88023`), its source-answer KL is `1.199` versus `1.937` for direct source-heavy training; source-query answer accuracy is `.447` versus `.235`. Section-key accuracy is `.883` versus `.900`. It improves source speaker-edit error from `2.002` to `1.553`, but source **query-object** edit error remains `2.018` versus `2.028`. Thus the curriculum yields an early predictive/source-edit gain while the decisive key-binding behavior is still missing at 600 joint updates. The curriculum arm used 1,500 extra short updates, so this is a schedule comparison at matched *joint* updates, not a total-compute-matched comparison.

Both arms received the same additional 600 joint updates (seed `302`, restarted optimizer, otherwise matched training settings), then were compared on a new panel (`88031/88032/88033`) from the **original** v8 distribution. At 1,200 joint updates, direct versus curriculum source-answer oracle KL is `1.500` versus `0.933`, source query-answer accuracy `.331` versus `.562`, and section-key accuracy `.971` versus `.963`. The curriculum model now responds somewhat to a source query-object edit (native effect L1 `.360`, versus `.058` direct), but the exact-oracle effect is L1 `2` and its effect-to-oracle error is still `1.831` (versus `2.038` direct). Worse, an irrelevant other-speaker edit with zero oracle effect moves the curriculum model by `.703` L1. It has begun to learn source-key sensitivity but remains poorly selective. Its section-key effect error is `.195`, close to direct `.146`; both are genuinely section competent on this panel. These are 80 source-query and 120 section-key edit pairs, not a broad natural-language evaluation.

This changes the interpretation gate: a model can be studied on any **individual task it demonstrably learns**, without waiting for every rule in the broad stream to work. Cross-task reuse claims require the same model to pass both relevant tasks. The direct and curriculum models qualify for section-scope analysis; neither yet qualifies as a clean source-binding teacher. Source curricula, frequency changes, or larger models are follow-ups only if source binding itself is the target. The toy language's realism relative to FineWeb remains a separate, unfinished validation task.
