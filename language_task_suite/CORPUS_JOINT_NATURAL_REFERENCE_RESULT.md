# Unedited FineWeb reference stream for three local rule families

The [reference generator](corpus_rule_reference_dgp.py) now tags naturally repeated three-letter codes alongside numbered-list continuation and bracket closing in the **same unedited FineWeb documents**. This is a source-unconditioned reference arm: it scans consecutive source offsets, keeps every document regardless of whether a rule is present, and trains on ordinary next-token prediction throughout each chunk. The local labels identify candidate sites for stratified behavioral and causal evaluation; they are **not** an exact oracle for the other tokens. The earlier transformed list, bracket, and nonce arms remain available at explicit nonzero rates.

The [auditor](audit_corpus_rule_reference_dgp.py) scanned two independent 5,000-document panels, offsets 413,000–417,999 and 418,000–422,999 in FineWeb `sample-10BT`. List and bracket selectors were enabled with identity transformations (zero list shift and no square conversion); nonce editing was disabled; `literal-copy-rate=1` only enabled tagging. It tested nonoverlapping 256- and 512-token chunks over the same documents, capped at 2,048 source tokens per document. A site counts as local only when the source and answer are in one chunk with compatible BPE offsets. Natural-code labels further require the two visible occurrences to be the **same single BPE token**. No source prose is stored in the published aggregates.

| 512 | 10,000 | 123 | 2,998 | 765 | 223 | 32 | 9 | 3 |

These are **not** mutually exclusive document counts. The 256-token panels contain 27,112 model chunks and 5,691,952 valid next-token positions; the 512-token panels contain 16,469 chunks over the same valid positions. The natural-code sites total 1,452 at 256 tokens and 1,805 at 512. All four audits report zero edited documents. Longer context increases visible bracket+code pairs by about 70% on the same sources, but three-way contexts remain exceptionally rare. Document-level co-occurrence is more common than same-chunk co-occurrence, so document-wide counts would overstate the task combinations available to these models.

The [synthetic fixture](check_corpus_rule_reference_dgp.py) checks a document with all three tagged families, unchanged text, and each source/answer visible in an ordinary model chunk. This verifies the joint tagging and chunk accounting. It does not verify that a model learns all three rules.

The code detector is deliberately a **literal-repeat proxy**, not a semantic acronym/entity oracle. Manual review of eight reservoir-sampled code excerpts found a repeated uppercase `PER` used as ordinary prose; other examples included organization/technical codes such as `BBC` and `HIV`. Thus exact surface equality alone is insufficient to label a semantic copy dependency. A natural code may also be predictable from local lexical context or frequency without retrieving its earlier occurrence. Before interpreting any weight path as a code-copy circuit, require held-out source/code combinations, a source-masked or source-scrambled baseline, and in-support source-edit tests. The present audit establishes opportunities, not competence or causal reliance.

This is a better realism reference for the existing task suite because the full training text is drawn from FineWeb without selection or replacement. It does **not** imply that a 10,000-document slice matches the corpus-wide Zipf curve, that list/bracket/code labels capture all rules in the text, or that the full natural next-token distribution is symbolically known. The next data-design choice is to add other naturally frequent, independently checkable rule families or a sampled document/world-state process that makes composition common enough to train and test, while keeping whole-task holdouts. Weight-based canonicalization and sparsity comparisons should use only rules that first pass behavioral and causal gates, and should report reconstruction, task prediction, and intervention fidelity separately.
